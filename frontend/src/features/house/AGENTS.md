# 끼끼의 집 (house) 작업 규칙

마스코트의 집 화면. 홈이 아니라 "놀러 오는 곳"이며, 이번 주 성과는 성적표가 아니라
조용한 한 줄로 둔다.

상위 규칙은 루트 `AGENTS.md`와 `frontend/AGENTS.md`를 따른다. 이 문서는 그 위에
집 화면에만 해당하는 제약을 더한다. 충돌하면 상위 문서가 우선이고, 임의로 고르지 말고
멈추고 물어본다.

## 1. 파일 구성

| 파일                     | 역할                                                                                                          |
| ------------------------ | ------------------------------------------------------------------------------------------------------------- |
| `houseModel.ts`          | 순수 규칙. 바나나 적립·지출, 친밀도, 일일 퀘스트, 배경 선택, 소품 좌표, 방문 연속, `HouseView` 생성           |
| `houseStorage.ts`        | 로컬 영속 어댑터(`HouseStore`). web은 `localStorage`, 그 외는 프로세스 메모리                                 |
| `houseArtSlots.ts`       | 방·포즈·가구 자산 슬롯 선언                                                                                   |
| `HouseArt.tsx`           | 슬롯 렌더러(자산 없으면 라벨 플레이스홀더) + 바나나·하트·불꽃·클립보드·전구·＋·＞·ⓘ 글리프                    |
| `MascotHouseContent.tsx` | 프레젠테이션 전용. 값은 `HouseView`로 받고 입력은 그대로 위로 넘긴다. 탭바도 `footer`로 받아 배경 안에 그린다 |
| `MascotHouseScreen.tsx`  | API + 로컬 상태 컨테이너                                                                                      |

테스트는 `tests/houseModel.test.ts`(규칙)와 `tests/MascotHouseScreen.test.tsx`(화면)에 있다.

규칙은 `houseModel.ts`에만 둔다. 화면 파일에 계산식을 새로 만들지 않는다.

## 2. 서버와의 경계

- 서버에서 읽는 값은 둘뿐이다: `GET /weeks/{week_start}`(주간 목표·마감 여부),
  `GET /workout-sessions`(완료 기록).
- **바나나·꾸미기·방문 기록은 서버에 없다.** 전부 기기 로컬이며 `HouseStore` 뒤에 있다.
  API가 생기면 `houseStorage.ts`만 교체하고 화면은 건드리지 않는다.
- 루틴은 읽지 않는다. 최종 루틴은 홈이 보여주는 값이고, 여기서 다시 보여주면
  동기화 지점이 둘로 늘어난다. `getCurrentRoutine`을 이 화면에 다시 넣지 않는다.
- 로컬 저장 대상은 카운터·아이템 id·배경 id·정규화된 소품 좌표·로컬 날짜뿐이다.
  토큰·이메일·이름·건강 기록·체크인 값은 절대 넣지 않는다.
- 기기 단위 저장이다. 사용자별 키는 식별자를 저장한다는 뜻이라 쓰지 않으며,
  한 기기에서 두 계정이 같은 집을 본다. 서버가 이 상태를 갖게 되면 해소된다.
- 주간 요청이 실패해도 화면을 대체하지 않는다. 방은 그대로 두고 실패를 인라인으로
  알리며 재시도를 제공한다. 주간에 의존하는 값은 추측하지 말고 "알 수 없음"으로 떨어뜨린다.

## 3. 깨뜨리면 안 되는 불변식

- **차감 금지.** 미수행·중단·미방문으로 바나나가 줄거나 만료되거나 이미 받은 보상이
  취소되는 규칙을 추가하지 않는다. 지출은 사용자가 누른 행동에서만 일어난다.
- 안전 중단(`STOPPED_FOR_SAFETY`)은 일부 완료(`PARTIAL`)와 같은 양을 지급한다.
  아파서 멈춘 날이 손해가 되면 안 된다.
- 실망하는 마스코트 포즈는 없다. `HousePose`에 그런 값을 추가하지 않는다.
  `restingPose`는 목표 달성 시 올라가되 미달로 내려가지 않는다.
- 오늘 운동하라고 재촉하는 문구·배지·알림을 넣지 않는다. 휴식을 택한 사용자에게
  이 화면이 압박이 되면 안 된다.
- 공식 완료 판정은 서버 세션 상태에서만 온다. 바나나는 그 상태를 읽을 뿐 정의하지 않는다.
  경과 시간·방문 기록으로 완료를 추정하지 않는다.
- 보상 지급은 세션 id 기준으로 멱등해야 한다. 목록을 다시 읽어도 두 번 주지 않는다.
- 재화 수치(적립량·비용)는 도메인 문서에 없는 신규 규칙이다. 바꾸려면 PM·도메인 승인이
  필요하며, 임의로 조정하지 않는다.
- **쓰다듬기는 무료이며 횟수 제한이 없다.** 비용이나 일일 상한을 다시 넣지 않는다.
  상한은 친밀도 적립(`INTIMACY_DAILY_EARN_LIMIT`)에만 걸리고, 다 쓴 뒤에도 터치는
  그대로 받아 반응한다. `petMascot`이 실패를 돌려주는 형태로 바꾸지 않는다.
- **친밀도는 내려가지 않는다.** 미접속·미수행으로 포인트나 레벨이 깎이는 규칙을
  추가하지 않는다. 획득처는 쓰다듬기·바나나 주기·운동 완료 셋이다.
- **퀘스트 미달은 손해가 아니다.** 미달에 경고색·`아직`·재촉 문구·집 화면까지 따라오는
  배지를 붙이지 않는다. 휴식일은 `0 / 1`로 남는 것이 전부이며, 주간 목표만 채우면 된다.
- 일일 퀘스트 지급은 `questLocalDate` 기준으로 하루 안에서 멱등하다. 상태를 여러 번
  저장해도 두 번 주지 않는다.
- 저장 스키마를 올릴 때 구버전 payload를 버리지 않는다. 버리면 이미 받은 바나나가
  0으로 돌아가고, 그것은 차감 금지 위반이다. `parseHouseState`에서 마이그레이션한다.

## 4. 레이아웃

- 배경 컨테이너는 **전체 화면**이다. 상태바 아래와 탭바 뒤까지 깔리며, 카드나 프레임
  안에 넣지 않는다. 나머지 요소는 전부 그 위에 뜬다. 실제 일러스트는 이전 `cover`
  크기의 `HOUSE_BACKDROP_ZOOM`(현재 `0.5`)만큼 축소해 상단에 고정하고 가로 중앙에 둔다.
  아래쪽에 그림이 부족한 영역은 **활성 배경 이미지 하단 160px 영역을 크게 블러한
  연장부**로 이어 붙인다. 연장부는 원칙적으로 `바나나 주기` 버튼과 하단 타일 패널 사이
  간격의 중앙에서 시작한다. 단, 실제 표시된 이미지의 하단이 그 지점보다 위라면 이미지
  끝 48px 전부터 알파 마스크로 블러를 섞고 이미지 끝에서 완전한 블러 연장부가 되게 한다.
  즉 블러 시작점은 `min(조작부 경계, 표시 이미지 끝 - 48px)`이며, 이미지 표시 높이를
  조정하면 시작점도 자동으로 함께 움직인다. 잘못된 0 좌표로 화면 전체를 블러하지 않고,
  모바일과 웹 모두 같은 상대 레이아웃 좌표를 사용한다. 세로형 화면에서 기본 50% `cover`
  높이가 부족하면 표시 이미지 높이를 최소 `조작부 경계 + 48px`까지 종횡비를 유지해
  확대한다. 이미 충분히 큰 웹 배경은 확대하지 않는다. 시작점 아래는
  `colors.canvas`로 페이드한다. 마지막 1픽셀 행을 세로로 늘리면 줄무늬가 생기므로 쓰지
  않는다. 고정된 단일 시작색이나 반전 이미지도 쓰지 않는다. 그래야 배경이 바뀌어도
  이미지 하단 색을 따라가면서 경계와 세로 줄무늬 없이 이어진다. 소스 크기는 자산에서
  동적으로 읽는다.
- 화면 하단은 `colors.canvas`로 페이드해서 배경이 기기 가장자리에서 끊기지 않게 한다.
  페이드 색은 `fadeFrom()`으로 토큰에서 만들어 쓴다. rgba를 손으로 적지 않는다.
- 탭바는 `MascotHouseScreen`이 `footer`로 넘기고 `MascotHouseContent`가
  배경 안에서 그린다. 컨테이너가 배경 밖에 따로 그리면 배경이 탭바 뒤에서 끊긴다.
- **화면 비율 대응:** 배경의 기준 크기는 `cover`로 계산한 뒤 50%로 축소한다. 이미지
  상단은 화면 최상단에 고정하고 가로 중앙을 유지한다. 남는 가로 크롭이 있으면 좌우
  바깥쪽부터 대칭으로 잘리게 한다.
  조작부는 Large phone 프리뷰의 상대 위치를 기준으로 화면 가로폭 전체를 사용하고,
  좌우 여백은 픽셀이 아닌 화면 폭의 비율로 둔다. 따라서 휴대폰 폭이 달라도 같은
  상대 위치를 유지하고, 넓은 웹에서도 고정 폭 열의 안쪽으로 몰리지 않는다.
  화면이 기준 비율보다 짧으면 가로와 세로 중 더 부족한 축에서 계산한 동일 배율을
  상단 칩, 행동 버튼, 하단 타일과 탭에 함께 적용한다. 터치 버튼 높이는
  44px 아래로 줄이지 않는다.
- 말풍선 문구는 `houseSpeech()`가 만든다. 화면 파일에 문구를 직접 적지 않는다.
- 말풍선은 처음 나타나거나 문구가 바뀐 뒤 5초가 지나면 사라진다. 새 반응 문구가 생기면
  다시 5초 동안 표시한다.
- 상단에는 제목만 둔다. 홈·마이페이지는 탭바에 이미 있으므로 모서리 버튼으로
  중복해서 만들지 않는다.
- 상단 칩은 좌측 레일에 바나나, 가운데에 친밀도, 우측 레일에 집 꾸미기·방문 연속으로
  둔다. 레일은 절대 배치라 서로 밀지 않으므로, 마스코트 바닥값이 쓰는 상단 레일 높이는
  세 레일 중 **가장 큰 값**으로 계산한다. 일부만 실측하면 다른 칩에 마스코트나 소품이
  가릴 수 있다.
- 상단 바나나·집 꾸미기·친밀도·방문 연속 칩은 배경이 비치는 반투명 면을 쓴다.
  바나나 칩의 `+`, 친밀도 칩, 친밀도 보너스 행, 퀘스트 타일은 모두 오늘의 퀘스트를 연다.
- 집 화면의 상호작용 결과에는 성공·경고를 포함한 별도 안내 문구나 입력을 막는 피드백
  오버레이를 띄우지 않는다. 다만 사용자가 직접 실행한 구매·바나나 주기·쓰다듬기에는
  실제 차감량 또는 반짝임을 보여 주는 짧은 비차단 장식 효과를 허용하며(쓰다듬기는
  무료라 차감 칩 없이 반짝임만 뜬다), 효과는 자동으로
  사라져야 한다. 차감량은 좌측 상단 보유 바나나 칩에, 바나나 주기의 작은 바나나 효과와
  쓰다듬기의 별 효과는 마스코트 위에 별도 레이어로 겹친다. 효과 동안에도 마스코트 에셋은
  계속 렌더링되어야 한다. 그 외에는 배경 선택 상태, 버튼 비활성화, 바나나 잔액, 마스코트 포즈처럼
  화면에 이미 존재하는 변화로 결과를 전달한다. 주간 목표를 불러오지 못한 경우에도 별도
  알림을 만들지 않는다. 포즈 변경 때문에 `stage`와 마스코트
  위치가 움직이면 안 된다. `mascotSlot`은 전체 화면에 절대 배치하고 위치는
  `houseMascotTop()`이 픽셀로 계산한다(§4의 가림 방지 규칙 참고). 기준선은 화면 높이의
  45%에서 마스코트 높이의 절반을 뺀 값이고, 기본 높이를 넘는 세로형 화면에서는 늘어난
  높이의 10%만큼 최대 50px까지 아래로 따라가게 하여 확대되는 배경에 비해 마스코트가
  위로 떠 보이지 않게 한다. 마스코트 크기도 초과 높이의 4%만큼 키우되 111px에서 시작해
  최대 126px로 제한하고, 말풍선은 바뀐 크기를 기준으로 마스코트 위에 붙인다. 말풍선과
  배치 아이템은 이 슬롯을 기준으로 따라가며 좌표 계산에 참여하지 않는다.
- **하단 패널 높이는 고정이다.** `houseBottomPanelTop`은 조작부 전체가 아니라
  **마지막 패널(`house-play-panel`) 자체의 높이**만 읽어 배경의 최소 배율과 블러
  연장부 시작점을 정한다. 따라서 그 패널의 안쪽 높이는
  `HOUSE_PANEL_CONTENT_HEIGHT`(150, 패딩 포함 182)에 고정한다. 이 값이 흔들리면
  마스코트는 그대로인데 배경만 줄어들어 화면이 어긋난다. 더 많은 공간이 필요한
  요소는 패널 **위**에 쌓는다 — `stage`가 `flex: 1`로 흡수하므로 패널 하단과 배경은
  움직이지 않는다. 친밀도 보너스 행이 카드 아래가 아니라 위에 있는 이유가 이것이다.
- **마스코트와 그 아래 터치 안내는 조작부에 절대 가리면 안 된다.** 이것이 위치 규칙의
  목적이고, 45% 기준선은 그 목적을 위한 기본값일 뿐이다. `houseMascotTop()`은 기준선을
  쓰되, 실측한 조작부 상단(`houseControlsTop()` = 컬럼 하단 − `actionAreaHeight`)에서
  `HOUSE_MASCOT_CONTROL_CLEARANCE`와 터치 안내 높이를 뺀 선까지만 허용하고, 넘치면
  그만큼만 위로 올린다. 여유가 있으면 기준선 그대로 둔다.
  입력은 전부 `onLayout` 실측값이다 — 기기 목록이나 화면비 분기를 넣지 않는다.
  그래야 모든 휴대폰 화면비와, 창 크기가 임의인 웹에서 같은 규칙이 성립한다.
  바닥값은 상단 칩 아래(`stage` 상단 + 상단 레일 높이)다. 둘 다 담기에 너무 짧은
  화면에서는 칩 뒤로 올라가지 않고 거기서 멈춘다.
- 조작부 높이를 바꾸는 요소를 추가하면 `tests/MascotHouseScreen.test.tsx`의 가림 방지
  테스트가 함께 검증한다. 그 테스트의 화면비 목록(소형·기준·긴 휴대폰·폴더블·웹 창
  2종)을 줄이지 않는다.
- **쓰다듬기는 마스코트를 직접 눌러 실행한다.** 별도 버튼을 다시 만들지 않는다.
  `mascotSlot`은 `pointerEvents="box-none"`이고 마스코트만 `Pressable`로 감싼다.
  `Pressable` 크기는 `mascotSize`와 같게 두어야 앵커가 움직이지 않는다.
- 마스코트 아래 터치 안내(`house-touch-hint`)와 말풍선은 둘 다 `mascotSlot` 안의
  `position: 'absolute'` 요소다. 일반 자식으로 넣으면 열에 쌓여 마스코트가 밀린다.
- **집 꾸미기와 오늘의 퀘스트 패널은 오버레이다.** `바나나 주기`·친밀도 보너스·타일
  묶음(`actionStack`) 위에 `position: 'absolute'`로 덮으며, 그 묶음은 계속 마운트된
  상태로 둔다. 조건부로 교체하면 열 높이가 바뀌어 배경과 마스코트가 움직인다.
  패널 위쪽 끝은 `바나나 주기` 버튼의 윗변과 같고, 내용이 넘치면 패널 안에서
  스크롤한다 — 패널을 더 높이 키우지 않는다. 퀘스트를 별도 화면으로 바꾸지 않는다:
  화면을 교체하면 배경·마스코트·하단 탭바가 함께 사라진다.
- 하단 패널은 정사각 타일 2개(`바나나 받기`·`퀘스트`)를 한 행에 같은 크기로 그린다.
  제목 위의 설명문구와 플레이 시간 배지는 두지 않는다. 새 게임은
  `HOUSE_MINI_GAMES`에 id·제목·`limitLabel`·아이콘을 추가하고 같은 행에 넣으며,
  `MascotHouseScreen`에서 해당 화면을 연결한다. 패널을 높이지 않는다.
- 바나나 받기는 하루 `HOUSE_GAME_DAILY_PLAYS`회만 열린다. 소진 뒤 타일은 비활성이고
  `오늘 1/1 완료` 배지를 단다. 소진을 실패·경고로 표현하지 않는다.
- 하단 탭바는 이 작업 범위가 아니다. `HomeBottomNavigation`과 `footer` 전달 구조를
  바꾸지 않는다.
- 집 꾸미기는 `배경`과 `소품` 탭으로 나눈다. 배경은 검수된 후보를 미리보기로 보여 주고
  무료로 전환하며 선택 id를 `HouseStore`에 저장한다. 소품의 기존 구매·배치 규칙은
  그대로 유지한다.
- 배경과 소품 후보는 패널 안의 세로 스크롤 목록으로 제공한다. 소품 카드는 사용 가능한
  너비를 3등분해 같은 행의 불필요한 여백을 남기지 않는다.
- 구매한 소품은 집 꾸미기 패널이 열려 있을 때만 터치 또는 마우스 드래그로 옮길 수 있다.
  `닫기` 뒤에는 입력을 받지 않고 마지막 위치를 유지한다. 위치는 화면 크기와 무관한
  0~1 상대 좌표로 저장한다. 배치 소품의 점선 외곽선은 평상시에는 표시하지 않고,
  집 꾸미기 패널이 열려 위치를 조정할 수 있는 편집 모드에서만 표시한다. 소품은 실측한
  상단 버튼 묶음의 하단과 하단 조작부의 상단 사이에만 있어야 하며, 기존 저장 좌표도 이
  경계 안에서 표시한다. 버튼과 소품 사이에는 `spacing.sm` 간격을 둔다.
- 구매 목록의 소품 미리보기 크기는 유지하고 방에 배치된 소품만 기준 44px 대비 개별
  배율을 적용한다. 충돌 경계와 드래그 좌표는 배율이 적용된 실제 크기로 계산한다.
- 레이어 순서는 배경·배치 소품·화면 조작부·`mascotSlot` 순이다. 따라서 끼끼와 말풍선은
  모든 이미지 에셋보다 항상 위에 그린다.

## 5. 자산

`houseArtSlots.ts`의 슬롯 중 `source`가 `null`인 항목은 아직 그림이 없다.
검수된 자산만 연결하고, 나머지는 같은 크기의 라벨 플레이스홀더로 그린다.
그림이 도착하면 `source` 한 줄만 바꾸면 되고 레이아웃은 움직이지 않는다.

배경(`houseBackgroundArt`)만 예외다. 전체 화면 배경에 점선 플레이스홀더가 보이면
버그로 읽히므로, 그림이 없는 동안에는 `HOUSE_BACKDROP_FALLBACK` 그라데이션
(하늘→나무→풀→길)을 대신 그린다. `source`를 채우면 그라데이션은 자동으로 사라진다.

- 현재 연결됨: 배경 4종(`morning_camp.png`, `temp_back_dinner.png`,
  `kkikki_indoor.png`, `snowing_onsen.png`; 아침 캠핑장이 기본값), 포즈 5종 전부
  (`monkey_01.png` 임시 공용)
- 대기 중: `happy`·`eating`·`petted`·`resting` 전용 포즈, 가구 7종
- 마스코트는 현재 `stage` 하단의 `mascotSlot`에서 가운데 정렬되고 `111×111` 프레임에
  `contain`으로 표시된다. 새 배경에 맞춘 최종 위치·크기는 시각 확인 후 별도 확정한다.
- 컨셉 참고: `frontend/design-assets/house/concepts/kkikki-house-asset-system-concept-v1.png` (컨셉 시트이며
  프로덕션 자산이 아니다. 잘라서 임시 자산으로 넣지 않는다.)
- 아이콘은 `TabIcon`처럼 View로 그린다. 아이콘 패키지를 추가하지 않는다.

## 6. 검증

`frontend/`에서 실행한다.

```
npx.cmd prettier --write <변경한 파일들>
npm.cmd run lint
npm.cmd run typecheck
npx.cmd jest tests/houseModel.test.ts tests/MascotHouseScreen.test.tsx --runInBand
npm.cmd run build:production
```

규칙을 바꿨으면 `tests/houseModel.test.ts`를 함께 고친다. 상수를 참조하는 테스트라
값만 바꿔도 통과하는 경우가 있으니, 의도한 동작 변화가 테스트로 드러나는지 확인한다.

전체 스위트(`npm.cmd run test`)에서 `tests/PreviewGallery.test.tsx`의 2건은
주간 리포트 쪽 기존 실패다(집과 무관, `HEAD`에서도 실패). 새로 깨진 것과 구분한다.

## 7. 미리보기

`npm.cmd run web` 후 `http://localhost:8081/?preview=mascot-house`.
실제 휴대폰의 현재 Chrome 콘텐츠 영역으로 직접 확인할 때는
`http://<개발-PC-IP>:8081/?preview=mascot-house&viewport=device`를 사용한다. 이 모드는
기기 프리셋, 갤러리 여백, 캔버스 축소를 적용하지 않는다.
갤러리의 끼끼의 집 탭도 이 화면으로 온다(`HOME_TAB_SCREENS.house`).
`Home map`은 `Home-p2 v1.dc.html` 전사본으로 갤러리 목록에 그대로 남아 있다.
갤러리는 고정 시각(2026-08-22)과 메모리 스토어를 쓰므로 매번 같은 상태에서 시작한다.
화면은 `now`와 `store`를 주입받으므로 테스트도 시계·저장소에 의존하지 않는다.
