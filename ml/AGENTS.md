# ML working rules

이 디렉터리는 **운동 수행 여부 예측 ML 과제**의 오프라인 분석 코드다.
작업 전 `ml/docs/ML_WORK_PLAN.md`를 읽는다.

## 1. 범위

- 이 과제는 **오프라인 분석 전용**이다. 런타임 결정에 연결하지 않는다.
- `ml/` 밖의 파일을 수정하지 않는다. `backend/`, `frontend/`, `data/`, `docs/`는 건드리지 않는다.
- 자기 트랙 소유 파일만 수정한다 (`ml/docs/ML_WORK_PLAN.md` 8절).
- 딥러닝을 사용하지 않는다. 표 형식 데이터이며 GBDT 계열로 충분하다.

## 2. 데이터

- **`ml/data/`는 이 과제의 Kaggle 합성 데이터다.** 저장소 루트 `data/`(운동 카탈로그·안전 규칙
  도메인 데이터)와 다른 영역이며 섞지 않는다.
- 실사용자 데이터를 이 과제에 투입하지 않는다.
- 출처 URL, 라이선스, 취득일, **합성 데이터 여부**를 기록한다.
- 원본 대용량 파일을 커밋하지 않는다. 취득 스크립트와 체크섬을 커밋한다.
- **데이터셋은 Whoop Fitness Dataset 100K 하나만 사용한다.** 다른 데이터셋을 추가하지 않는다.
- 실측: 100,000행 / 286명 / 2023-01-01~2024-02-03 / 39컬럼 / 기저율 0.5401.

## 3. 타깃

```text
workout_completed = 1  해당 날짜에 운동 기록 있음
workout_completed = 0  해당 날짜에 운동 기록 없음
```

이것은 **활동 발생 여부**이지 제품의 공식 수행 상태가 아니다.
제품의 공식 상태는 `COMPLETED` / `PARTIAL` / `NOT_COMPLETED` 3값이며 앱 내 블록 체크로만 확정된다
(`docs/DOMAIN_RULES.md` 463, 476행). 이진화로 `PARTIAL`이 소실된다는 점을 결과서에 명시한다.

## 4. 누수 차단

다음 컬럼은 운동 수행 후 생성되거나 타깃을 직접 노출하므로 **입력에서 제외한다.**

- 당일 `activity_type`, `activity_duration_min`, `activity_strain`, `activity_calories`
- 당일 `avg_heart_rate`, `max_heart_rate`, `hr_zone_1_min`~`hr_zone_5_min`
- 당일 `workout_time_of_day` (미수행일 결측 -> 타깃 직접 노출)
- **당일 `day_strain`, `calories_burned`** — 이름에 activity가 없지만 당일 운동이 섞여 있다
- **`hrv_baseline`, `rhr_baseline`** — 사용자당 전기간 상수. 미래 정보 + 사용자 지문

전일로 이동(`shift(1)`)한 값은 누수가 아니며 `A3`/`A5`에서 사용한다.
개인 기준선이 필요하면 `hrv_baseline`을 쓰지 말고 직전 28일로 **직접 인과 계산**한다.

`validate_leakage.py`는 이 컬럼들이 최종 데이터셋에 없음을 단언하고, 하나라도 있으면
**예외를 던지고 중단한다** (fail closed). 경고만 출력하고 넘어가지 않는다.

## 5. 전처리

- `user_id + local_date`로 정렬한 뒤 컨디션 값을 `shift(1)`로 전일 기준으로 옮긴다.
- 롤링 피처(7일·28일)는 **사용자별 시간순으로 인과적으로** 계산한다. 미래 값을 포함하지 않는다.
- **결측을 0으로 채우지 않는다.** 웨어러블 미착용과 "HRV 0"은 다르다.
  사용자별 중앙값 또는 최근 관측값을 쓴다.
- **이 데이터셋에는 웨어러블 결측이 없다** (유일한 결측은 누수 컬럼 `workout_time_of_day`).
  가용성 플래그를 만들지 마라. 전 행이 True인 분산 0 컬럼이 된다.
- 컬럼명은 `ml/docs/FEATURE_SPEC.md`를 단일 기준으로 삼는다. 임의로 만들거나 바꾸지 않는다.

## 6. 분할

- **무작위 분할(`train_test_split` 기본값)을 쓰지 않는다.** 같은 사용자의 인접일이
  학습과 평가에 동시에 들어간다.
- 시간 기반(과거 70 / 다음 15 / 마지막 15)과 사용자 기반(70 / 15 / 15) 두 벌을 만든다.
- 하이퍼파라미터는 validation으로만 조정한다. **test는 최종 1회만 사용한다.**

## 7. 모델 산출물

- 전처리를 포함한 **sklearn Pipeline 객체를 통째로** `joblib` 저장한다. 분리 저장하면 재현이 깨진다.
- 선정 기준은 **validation PR-AUC**다. test 성능을 보고 고르지 않는다.
- `MODEL_CARD.md`에 학습 데이터·피처·타깃 한계·성능·선정 근거·**사용 금지 범위**·
  seed·git_commit·라이브러리 버전을 적는다.
- 저장한 모델을 다시 로드해 예측이 재현되는지 확인한다.

## 8. 평가와 보고

- 정확도만 보고하지 않는다. Precision, Recall, F1, ROC-AUC, PR-AUC, **Brier**,
  calibration curve, confusion matrix를 모두 낸다.
- **세그먼트별 성능을 반드시 보고한다**: 이력 길이(0-7 / 8-28 / 29+), `experience_level_code`.
  웨어러블 유무 세그먼트는 불가능하다(결측 없음). `A2` vs `A3` ablation이 대신 답한다.
  이력 길이 세그먼트가 가장 중요하다. 서비스 타깃이 운동 초보자·복귀 사용자이므로
  콜드스타트 구간 성능이 실질적인 상한이다.
- 피처 중요도는 **합성 생성기의 특성일 수 있다.** 실사용자 행동 가설로 승격하지 않는다.

### 표현 규칙

| 금지 | 허용 |
|---|---|
| 실제 운동 성공확률 | 합성 데이터 기준 수행 성향 점수 |
| 계획한 운동의 성공 여부 | 해당 날짜의 운동 기록 존재 여부 |
| 웨어러블은 예측에 도움이 안 된다 | 이 합성 데이터셋에서는 추가 기여가 관측되지 않았다 |
| 최근 수행률을 높이면 성공률이 상승한다 | 합성 데이터에서 최근 수행률이 주요 예측 특성으로 나타났다 |

인과 주장을 쓰지 않는다.

## 9. 제품 불변조건 (`docs/DOMAIN_RULES.md`)

ML은 다음을 **절대 수행하지 않는다.** `MODEL_CARD.md`에도 명시한다.

- 통증·이상 반응 판단
- 안전 veto 생성 또는 변경
- `REST` / `STOP_AND_SEEK_HELP` 결정
- 운동 강도·난이도 결정
- 사용자 요청 시간 단축
- 웨어러블만으로 계획 변경
- 운동 완료 상태 자동 판정
- 미수행 가능성을 근거로 한 압박 알림

`docs/DOMAIN_RULES.md` 421행은 opaque confidence 점수를 MVP 에이전트 계약에서 배제하고,
441행은 후보 점수화를 결정적 Python 규칙의 영역으로 지정한다.
연속 점수를 에이전트에 연결하려면 계약 변경과 개발 리드 승인이 선행된다. **이번 범위 밖이다.**

## 10. 재현성과 검증

- 모든 스크립트에 시드를 고정한다.
- 실험 결과에 `git_commit`을 기록한다.
- 노트북 결과를 최종 산출물로 삼지 않는다. 스크립트로 재현 가능해야 한다.
- **실행하지 않은 검증을 통과했다고 말하지 않는다.** 실행한 명령과 실제 출력을 제시한다.
- 의존성을 임의로 추가하지 않는다. 추가 시 `requirements.txt`에 버전을 고정하고 팀에 알린다.
- 포매터를 저장소 전체에 돌리지 않는다. `ml/`에만 적용한다.
