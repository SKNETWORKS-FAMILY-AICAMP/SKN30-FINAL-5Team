# ADR-0002: 멀티 에이전트 협업 및 안전 게이트 구조

- 상태: SUPERSEDED
- 날짜: 2026-08-11
- 소유자: 제품·개발 공동
- 승인자: 개발팀장(최종 설계 후 승인)
- 승인 증적: 사용자 명시 승인(2026-08-11, 본 작업 요청). PR 링크는 생성 후 연결
- 관계: ADR-0007로 대체됨
- 관련 요구사항/이슈: `F002`, `F029`, `POL-008`, `NFR-003`

## 배경

요구사항 정의서는 Training·Recovery·Safety proposal, Coordinator, FinalSafetyGate와 회의 UI를 요구한다. 그러나 입력 데이터와 에이전트 상세 로직은 아직 확정되지 않았다.

## 결정

- 세 proposal과 Coordinator, 독립된 FinalSafetyGate 구조를 상위 설계 경계로 채택한다.
- Coordinator는 검수된 후보 중 최종 루틴 하나를 선택하며 안전 veto를 해제하지 않는다.
- FinalSafetyGate와 실패 안전 규칙은 결정적으로 유지한다.
- proposal 스키마, 조정 순서, 버전 필드, 공개 요약은 데이터 확정 후 에이전트 로직 설계에서 정한다.
- 상세 proposal 스키마와 조정 순서는 구현 단계 2 전에 API·데이터·테스트 계약으로 별도 승인하며, 이 상위 경계를 바꾸려면 새 ADR을 작성한다.

## 결정 이유

요구사항의 에이전트·회의 UI 매핑을 유지하면서, 미확정 로직을 조기에 구현 계약으로 고정하지 않기 위해서다.

## 검토한 대안

- 기존 4개 에이전트 설명 유지
- 현재 문서에서 에이전트 구조를 모두 삭제
- 상세 proposal 스키마를 지금 확정

## 선택하지 않은 대안과 이유

- 기존 4개 구조는 최신 요구사항의 3개 proposal 구조와 충돌한다.
- 구조 삭제는 요구사항 추적성을 약화한다.
- 조기 스키마 확정은 데이터 확정 전 재작업 위험이 크다.

## 결과와 영향

관련 문서는 승인된 세 proposal·Coordinator·FinalSafetyGate 상위 구조를 사용한다. 이 ADR은 상세 구현 계약이나 최종 에이전트 로직까지 동결하지 않으며, 상세 스키마와 조정 순서는 별도 계약 승인 대상으로 남긴다.

## 보안·개인정보·호환성 영향

안전 veto는 LLM이나 Coordinator가 우회할 수 없고, 내부 프롬프트와 숨은 추론은 공개하지 않는다. 세부 공개 응답과 저장 필드는 별도 계약 승인 대상이다.

## 아직 확정되지 않은 사항

- 입력·출력 스키마, 조정 순서, 실패·재시도 규칙
- 공개 회의 UI 요약 필드와 표시 순서
- agent graph·policy·prompt 버전 관리 방식

## 후속 작업

1. 운동·사용자·웨어러블 데이터를 확정한다.
2. 데이터 기준으로 에이전트 로직을 설계한다.
3. 구현 단계 2에 진입하기 전에 상세 계약을 API·DATA_MODEL·TEST_STRATEGY와 함께 승인하고, 상위 경계가 달라지면 새 ADR을 작성한다.
