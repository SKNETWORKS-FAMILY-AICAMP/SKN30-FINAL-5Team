# ADR-0006: 캘린더 수행 여부 확인과 수동 외부 기록 범위

- 상태: ACCEPTED
- 날짜: 2026-08-12
- 소유자: 제품·개발 공동
- 승인자: 사용자 명시 결정(제품·개발 승인)
- 승인 증적: 사용자 명시 승인(2026-08-12, 본 작업 요청). PR 링크는 생성 후 연결
- 관련 요구사항/이슈: `F003`, `F004`, `F006`, `F007`, `F011`, `POL-004`, `POL-005`, `NFR-006`

## 관계

ADR-0001과 ADR-0003의 MVP 범위 중 수동 외부 기록 관련 결정을 부분 대체한다.

## 배경

캘린더·웨어러블·수동 외부 운동 기록이 공식 운동 수행 상태와 실제 기능 범위에서 혼동될 수 있다. MVP의 외부 연동 경계와 공식 판정 기준을 분리해 문서·API·데이터 모델·테스트의 기준을 고정한다.

## 결정

- 캘린더는 일정 조회, 운동 계획 일정 등록, 등록된 운동 일정의 수행 여부 확인만 지원한다.
- 캘린더에는 세부 운동·수행 시간·강도 기록을 저장하지 않으며, 캘린더 수행 여부 확인 결과는 보조 자료로만 사용한다.
- 캘린더 수행 여부 확인 결과는 앱 운동 블록의 `COMPLETED`, `PARTIAL`, `NOT_COMPLETED`, `STOPPED_FOR_SAFETY` 상태를 생성하거나 변경하지 않는다.
- 웨어러블 운동 데이터는 캘린더에 자동 등록하거나 기존 캘린더 일정을 자동 갱신하지 않는다.
- 수동 외부 운동 기록과 해당 기록 기반 칼로리 추정은 MVP에서 제외하고 추후 기능으로 분류한다.
- 웨어러블 미연동·권한 거부 사용자는 수동 체크인과 앱 운동 블록 체크로 핵심 흐름을 이용한다.
- 공식 운동 수행 상태는 앱 운동 블록의 명시적 체크 결과와 안전 중단 이벤트로만 확정한다.

## 결정 이유

캘린더와 웨어러블은 일정·컨디션 보조 기능으로 활용하되, 공식 수행 판정의 단일 기준을 앱 안에 유지해야 상태 재현성과 안전 검증을 보장할 수 있다. 수동 외부 기록을 MVP에서 제외하면 핵심 운동 실행 흐름과 후속 확장 기능의 경계도 명확해진다.

## 검토한 대안

- 웨어러블 운동 데이터를 캘린더 일정으로 자동 등록
- 캘린더 기록을 공식 운동 완료로 인정
- 수동 외부 운동 기록을 MVP에 포함

## 선택하지 않은 이유

- 웨어러블 자동 등록은 외부 데이터의 중복·오등록과 사용자 의도 불일치 위험이 있다.
- 캘린더의 일정 존재나 수행 여부만으로 어떤 운동 블록을 수행했는지 확인할 수 없다.
- 수동 외부 기록은 MVP 핵심 루프에 필수적이지 않아 API·저장·보유·테스트 범위를 확장한다.

## 결과와 영향

API와 데이터 모델은 캘린더 수행 여부 확인을 보조 경로로 표현하되 세부 운동 기록을 저장하지 않는다. `manual_activity_records`와 `/manual-activities` 계약은 문서에 남겨 후속 기능으로 표시하지만 MVP 공개 API·구현·테스트 범위에서는 제외한다.

## 보안·개인정보·호환성 영향

캘린더 본문과 웨어러블 원본은 기존 최소 수집·보유기간 정책을 따른다. 캘린더 수행 여부 확인은 최소 상태만 반환하고, 웨어러블 운동 데이터를 캘린더에 복사하지 않는다. 수동 외부 기록을 추후 도입할 때 별도 보유·삭제·호환성 검토를 수행한다.

## 아직 확정되지 않은 사항

- 캘린더 provider별 수행 여부 상태 제공 가능 범위
- 캘린더 수행 여부 확인의 세부 payload와 확인 시점
- 수동 외부 기록을 재개할 때의 provider·입력·보유기간 계약

## 후속 작업

1. 캘린더 provider 검토 시 수행 여부 확인이 불가능한 provider의 폴백 문구를 확정한다.
2. API·데이터 모델·요구사항·WBS·프로젝트 DOCX의 MVP 범위를 이 ADR과 대조한다.
3. 수동 외부 기록을 재개할 때 새 요구사항·migration·테스트를 별도로 승인한다.
