## 2. 서비스 한 줄 정의

운동 입문자와 복귀자의 **진척, 회복·안전, 실행 가능성, 지속 가능성**을 여러 전문 에이전트가 독립적으로 판단하고 조정해, 원래 목표를 잃지 않는 오늘의 실행 가능한 루틴으로 바꾸는 AI 운동 운영 서비스.

---

## 3. 핵심 제품 메시지

> AI가 새로운 루틴을 계속 만드는 것이 아니라, 기존 계획을 오늘 실행 가능하도록 조정한다.

본 서비스는 운동 영상이나 루틴을 더 많이 추천하는 서비스가 아니다.

사용자의 운동 계획이 수면, 피로, 통증, 일정, 장소, 장비, 운동 공백과 충돌할 때 다음을 결정한다.

- 기존 계획 유지
- 시간·세트·강도 축소
- 장소 또는 운동 방식 변경
- 회복 루틴으로 전환
- 휴식 권고

---

## 4. 핵심 타겟

### 4.1 1차 타겟

운동을 시작했거나, 중단 후 다시 시작하려는 운동 입문자·복귀자.

대표 상황:

- 헬스장에 등록했지만 루틴을 모름
- 홈트·유튜브 운동을 따라 하다 방향을 잃음
- 운동 공백 후 어느 강도로 재시작해야 할지 모름
- 일정·피로·통증으로 계획을 반복적으로 포기함
- 운동을 하지 못한 이유가 다음 계획에 반영되지 않음

### 4.2 2차 타겟

건강관리를 시작하고 싶지만 무엇부터 해야 할지 몰라 포기한 사용자.

초기 제품 메시지와 기능은 1차 타겟에 집중한다.

## 5. 해결하려는 문제

### 5.1 정보 과부하

사용자는 운동 정보가 없어서가 아니라, 너무 많은 정보 중 자신에게 맞는 시작점을 선택하지 못해 시작하지 못한다.

### 5.2 현실 조건과 계획의 충돌

수면 부족, 피로, 통증, 늦은 퇴근, 날씨, 장소, 장비 부족으로 원래 계획을 그대로 수행하기 어려운 날이 반복된다.

기존 대응은 대체로 다음과 같다.

- 무리해서 원래 계획을 수행
- 운동을 완전히 포기
- 다른 운동 영상을 다시 검색
- 놓친 운동을 다음 날 무리하게 추가

### 5.3 실패 이후 복귀 문제

한 번 운동을 놓친 뒤 기존 강도로 바로 복귀하려다 다시 실패하거나, 계획 전체를 폐기한다.

### 5.4 실패 원인의 미반영

많은 운동 서비스는 완료 횟수와 운동량은 기록하지만, 왜 하지 못했는지는 다음 추천에 충분히 반영하지 않는다.

## 6. 핵심 차별점

### 6.1 상충하는 목적의 협상

운동 계획은 하나의 기준으로 결정되지 않는다.

- 진척: 장기 목표와 주간 균형을 유지해야 함
- 회복·안전: 피로, 통증, 최근 운동 부하를 줄여야 함
- 실행 가능성: 현재 시간, 장소, 장비 안에서 가능해야 함
- 지속: 사용자가 실제로 시작하고 완료할 가능성이 높아야 함

본 서비스는 이 기준들을 하나의 불투명한 점수로 숨기지 않고, 독립된 전문 에이전트의 판단으로 분리한 뒤 조정한다.

### 6.2 목표 보존형 다운시프트

사용자가 희망한 운동 시간을 유지하면서 운동 목적과 수행 가능성을 함께 보존한다.

운동 동작은 다음과 같이 구분한다.

- `CORE`: 운동 목표를 유지하는 핵심 동작
- `SUPPORT`: 운동량과 균형을 보완하는 동작
- `OPTIONAL`: 시간이 있을 때 추가하는 동작

다운시프트는 사용자가 희망한 운동 시간을 임의로 줄이지 않고, 외부 부하·강도·세트·반복·운동 난이도·휴식 구성을 조정한다. 사용자가 당일 희망 시간을 직접 바꾼 경우에만 변경된 시간을 사용한다.

### 6.3 미수행 원인 학습

운동 미수행은 벌점이 아니라 다음 계획을 개선하는 신호로 사용한다.

예시:

- 시간 부족
- 피로
- 근육통
- 통증
- 일정 변경
- 장소·장비 문제
- 날씨
- 난이도
- 흥미 저하
- 동기 부족

### 6.4 복귀 정책

일정 기간 운동 기록이 없거나 연속 미수행이 발생하면 이전 루틴을 그대로 재개하지 않는다.

복귀 첫 운동은 다음 기준으로 보수적으로 조정한다.

- 요청 시간 유지
- 부하·강도·세트·반복 조정
- 익숙한 동작 우선
- 통증과 피로 재확인
- 결과에 따라 단계적으로 원래 계획 복원

## 7. 멀티에이전트 구조

### 7.1 진척 에이전트

목표:

- 장기 운동 목표 유지
- 주간 운동 부위와 운동량 균형 유지
- 지나치게 쉬운 운동만 반복되는 상황 방지

주요 입력:

- 기본 루틴
- 주간 운동 기록
- 운동 부위별 공백
- 사용자 목표
- 최근 수행 결과

### 7.2 회복·안전 에이전트

목표:

- 현재 상태에서 감당 가능한 운동 강도 판단
- 통증이나 위험 조건과 충돌하는 운동 제외

주요 입력:

- 수면
- 주관적 피로
- 근육통
- 통증 부위
- 최근 운동 부하
- 선택적 웨어러블 요약 데이터

안전 거부 결과는 다른 에이전트와 LLM이 무시할 수 없다.

### 7.3 실행 가능성 에이전트

목표:

- 현재 시간, 장소, 장비, 일정 안에서 실제 수행 가능한 계획 구성

주요 입력:

- 요청한 희망 운동 시간
- 현재 또는 예정 운동 장소
- 보유 장비
- 일정
- 선택적 날씨 데이터

### 7.4 지속 에이전트

목표:

- 사용자가 추천안을 실제로 시작하고 완료할 가능성 향상

주요 입력:

- 요일별 완료율
- 시간대별 완료율
- 운동 길이별 완료율
- 다운시프트 수락률
- 미수행 이유
- 사용자 조정 선호

### 7.5 조정 에이전트

목표:

- 전문 에이전트의 상충하는 제안을 조율
- 최종 추천안 1개와 더 가벼운 대안 1개 생성
- 변경 이유를 짧게 설명

## 8. 핵심 사용자 흐름

### 8.1 최초 진입

1. 회원가입 또는 로그인
2. 목표, 운동 경험, 장소, 장비, 가능 시간 입력
3. 주의 부위와 선호 입력
4. 보수적인 기본 루틴 생성

### 8.2 일일 이용

1. 오늘의 기본 계획 확인
2. 5초 체크인
   - 피로
   - 불편 부위
   - 희망 운동 시간 확인 또는 직접 변경
3. 전문 에이전트 판단
4. 조정 에이전트가 최종안 생성
5. 사용자가 다음 중 하나 선택
   - 추천대로 시작
   - 더 가볍게
   - 원래 계획 유지
   - 오늘은 휴식
6. 운동 수행
   - 최상단 0초 경과 타이머
   - 중앙 마스코트 애니메이션
   - 하단 운동 순서 블록과 자세·설명 펼침
   - 완료한 운동 블록 체크 후 다음 운동 이동
7. 블록 완료 상태로 전체·부분·미수행 계산
8. 운동 후 난이도와 통증 입력

### 8.3 미수행

1. 가장 큰 미수행 이유 하나 선택
2. 벌점이나 연속 기록 파괴 표현은 사용하지 않음
3. 다음 유사 상황에서 운동 길이, 장소, 시간, 강도를 조정
4. 장기 공백이면 복귀 정책 적용

### 8.4 주간 폐쇄 루프

1. 사용자 timezone 기준 월요일부터 일요일까지 한 주를 계산
2. 주가 닫힌 뒤 사용자가 요청하면 주간 수행·부분 수행·미수행과 주요 원인을 집계
3. 주간 리포트를 생성하고 사용자가 확인
4. 확인 결과를 바탕으로 다음 주 계획 생성 또는 수정
5. AI 수정은 최대 2회 제공하고 이후에는 사용자가 직접 편집
6. 직접 편집한 계획도 서버의 시간·장소·장비·안전 규칙을 다시 통과

웨어러블과 외부 운동 기록은 참고 신호일 뿐 공식 운동 완료를 확정하지 않는다. 공식 상태는 앱의 운동 블록 완료 체크로만 정하며 경과 타이머는 판정에 사용하지 않는다.

## 9. 대표 시나리오

### 9.1 정상 수행

입력:

- 컨디션 양호
- 통증 없음
- 희망 운동 시간 확인
- 장비 사용 가능

결과:

- 원래 루틴 유지

### 9.2 강도 다운시프트

입력:

- 기존 상체 근력 루틴 40분
- 희망 운동 시간 40분 유지
- 피로 MODERATE

결과:

- 핵심 밀기·당기기와 운동 순서 유지
- 부하·난이도·세트·반복·휴식 구성 조정
- 40분 권장 primary 제시
- 같은 40분 목표의 더 가벼운 강도 대안 제공

### 9.3 무릎 불편과 하체 진도 충돌

입력:

- 이번 주 하체 운동 미수행
- 무릎 불편
- 수면과 전반 피로 양호
- 집에서 희망 운동 시간 40분

결과:

- 힙브리지, 힙힌지, 코어 중심 12분 홈트
- 깊은 스쿼트, 런지, 점프 제외
- 원래 핵심 하체 루틴은 이후 상태 확인 후 재배치

## 10. 웨어러블의 위치

웨어러블은 필수 기능이 아니다.

미연동 사용자도 수동 체크인으로 동일한 핵심 경험을 사용할 수 있어야 한다.

웨어러블의 핵심 가치는 다음과 같다.

- 수면과 최근 활동 자동 입력
- 사용자 입력 부담 감소
- 최근 운동 이력 보조
- 개인 기준 대비 회복 신호 보완

초기 활용 데이터:

- 수면 시간
- 걸음 수
- 최근 운동 세션
- 운동 시간
- 안정 시 심박 추세

웨어러블 데이터만으로 안전이나 의료적 결론을 내리지 않는다.

---

## 11. 마스코트의 역할

마스코트는 장식이나 게임 캐릭터가 아니라 에이전트 판단을 사용자에게 번역하는 인터페이스다.

역할:

- 운동 전: 변경 이유를 한 문장으로 설명
- 운동 중: 상황별 간단한 동행 애니메이션
- 운동 후: 다음 계획에 무엇이 반영되는지 설명
- 미수행 후: 비난 없이 이유 수집과 복귀 안내

금지:

- 미수행에 대한 실망 표현
- 연속 기록 파괴 강조
- 통증 상황에서 장난스러운 표현
- 운동 정보보다 캐릭터가 더 눈에 띄는 구성

## 12. 제품 원칙

- 사용자는 하루에 한 개의 핵심 추천안을 본다.
- 더 가벼운 대안은 한 개만 제공한다.
- primary와 lighter는 사용자가 요청한 시간을 유지하고 수행 부담에서 차이를 둔다.
- 예상 시간과 0초부터 증가하는 실제 경과 타이머는 권장·기록 정보이며 완료 조건이 아니다.
- 운동 완료는 순서가 있는 운동 블록을 사용자가 명시적으로 체크한 결과로 판정한다.
- 완벽한 운동보다 지속 가능한 최소 실행을 우선한다.
- 운동 미수행은 벌점이 아니라 학습 신호다.
- 안전 규칙은 LLM보다 우선한다.
- 웨어러블 없이도 전체 핵심 흐름이 동작해야 한다.
- 의료 진단, 치료, 처방을 제공하지 않는다.
- 사용자가 휴식을 선택하면 그날 추가 압박 알림을 보내지 않는다.
- 주간 리포트를 확인하기 전에는 다음 주 계획을 최종 확정하지 않는다.
- 운동 시작과 지속에 직접 기여하지 않는 기능은 초기 범위에서 제외한다.

---

## 13. 제품 성공 기준

- 요청 시간을 보존한 강도 다운시프트 수락률
- 운동 블록 체크 기반 완료율
- 조정안 확인 후 운동 시작률
- 미수행 후 72시간 내 복귀율
- 일일 체크인 완료 시간
- 조정 이유 이해도
- 7일 이상 중단 후 첫 세션 완료율
- 통증 또는 불편 보고 후 안전한 대안 제공 성공률
- 닫힌 주의 리포트 생성·확인 완료율
- 리포트 확인 후 다음 주 계획 확정률
