## 목적과 비교 조건

이 실험은 V1 결정 경로를 싱글 에이전트라고 부르지 않는다. 싱글 조건은 현재
Training LLM Agent 한 번의 구조화 제안을 그대로 compiler와 integrity validator에
전달하는 ablation이다. 멀티 조건은 현재 V3 구조인 Training, Recovery, Feasibility의
병렬 제안과 Coordinator를 사용한다.

두 조건은 다음을 공유한다.

- 동일한 모델과 구조화 출력 어댑터
- 동일한 활성 승인 카탈로그에서 만든 운동 pool
- 동일한 합성 ConstraintEnvelope
- 동일한 compiler, 실제 카탈로그 시간 계산, integrity validator
- 실제 사용자 데이터가 아닌 식별정보 없는 합성 시나리오

실행 순서는 시나리오마다 싱글 우선과 멀티 우선을 교차했다. 운영 API 컨테이너와
설정은 변경하지 않았고 별도 one-shot 컨테이너에서만 `gpt-5.4`를 사용했다.

## 집계 결과

| 조건 | 최종 완료 | 무결성 통과 | fallback | Provider 호출 | 평균 지연 |
|---|---:|---:|---:|---:|---:|
| 싱글 Training | 0/4 | 0/4 | 0/4 | 5 | 8,495 ms |
| 멀티 V3 | 4/4 | 4/4 | 3/4 | 17 | 14,586 ms |

싱글의 토큰 합계는 입력 25,473, 출력 4,659였다. 멀티는 fatigue 시나리오의
schema-invalid 호출에 사용량 메타데이터가 없어 전체 합계를 확정할 수 없다. 메타데이터가
완전한 멀티 3건은 건당 입력 약 27천, 출력 약 2.9천~3.3천 토큰을 사용했다.

|---|---|---|---:|---:|---|
| 건강·일반 체력·30분 | 컴파일 실패 | 완료 | 예 | 270초 | MAIN만 |
| 제한 시간·일반 체력·20분 | 컴파일 실패 | LLM 계획 완료 | 아니요 | 144초 | 3단계 |

| 건강·근력 증가·30분 | 컴파일 실패 | 완료 | 예 | 270초 | MAIN만 |

멀티의 순수 LLM 계획 성공률은 1/4(25%)다. 4/4 완료는 멀티 LLM만의 성능이 아니라
결정론적 fallback을 포함한 시스템 전체 성능이다. fatigue 시나리오는 총 5회 호출 후
`LLM_AGENT_SCHEMA_INVALID`가 발생했고 fallback으로 완료됐다. 나머지 두 fallback 사례는
`V3_COMPILATION_FAILED` 이후 완료됐다.

싱글 조건은 네 시나리오 모두 Training 제안 생성에는 도달했지만 실제 카탈로그 시간으로
컴파일되는 단계에서 실패했다. 즉 모델이 주장한 요청 시간과 운동별 검수 시간 근거로 계산한
시간 사이의 불일치를 한 번의 제안만으로 교정하지 못했다. 멀티의 제한 시간 사례에서는
Coordinator가 이 조정 역할을 수행해 6개 운동, WARMUP/MAIN/COOLDOWN, 요청 대비 144초
오차의 유효 계획을 만들었다.

## 해석

이번 표본에서는 싱글 조건이 평균 42% 빠르고 provider 호출도 71% 적었지만 실행 가능한
계획을 하나도 만들지 못했다. 현재 구조에서 Recovery와 Feasibility 제안 및 Coordinator를
제거하면 비용과 지연은 줄지만, 실제 카탈로그 시간에 맞춘 계획 조정 능력을 잃었다.

반면 멀티 LLM 자체도 4건 중 3건에서 유효 최종 계획을 만들지 못했다. 현재 스테이징의 높은
가용성은 결정론적 fallback에 크게 의존한다. 따라서 이 결과는 "멀티 에이전트가 항상 더
우수하다"가 아니라, "현재 Training-only ablation보다 멀티+fallback 시스템이 훨씬
안정적이지만 멀티 LLM의 독립 성공률은 아직 낮다"로 해석해야 한다.

## 발견된 위험

멀티 fallback 3건은 모든 운동이 `MAIN` 단계였지만 integrity validator를 통과했다.
`PlanSpec`은 세 단계를 요구하지만 deterministic fallback과 최종 validator에는 같은 불변식이
없다. 사용자가 준비운동 없이 바로 본운동에 들어갈 수 있으므로 다음 비교 전에 우선 수정해야
한다.

## 한계와 다음 실험

- 시나리오당 1회, 총 4건이라 통계적 우열을 확정할 수 없다.
- 싱글 조건은 Training Agent prompt를 재사용한 ablation이며, 싱글 전용 통합 prompt를
  최적화한 별도 제품 후보가 아니다.
- 합성 envelope를 사용했으며 실제 사용자 품질이나 전문가 선호도를 측정하지 않았다.
- 승인된 가격 기준표가 없어 비용은 계산하지 않았다.
- 멀티의 일부 실패 호출에는 토큰 메타데이터가 없어 전체 토큰 합계 비교가 불가능하다.

다음 순서는 fallback에도 3단계 구성을 적용하고 validator에서 이를 검증한 뒤, 싱글 전용
통합 prompt를 별도 버전으로 정의하여 최소 3회 반복 및 전문가 블라인드 평가를 수행하는
것이 적절하다.
