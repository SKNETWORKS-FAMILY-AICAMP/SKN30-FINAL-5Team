# UI 휴식 통합과 운동 종료 흐름

- Primary owner: frontend
- Branch: `feat/ui-rest-flow-0908`
- 요청/범위: 프로젝트 소유자, 2026-09-08. 백엔드 수정 금지.
- 완료 범위: 현행 API를 유지한 프론트 호환 적용. 최종 제품 흐름의 서버 상태 통합과 0블록 무입력 종료는 [백엔드 전달 문서](HANDOFF-REST-OUTCOME-BACKEND.md)의 후속 작업이다.
- 최종 휴식 범위 추가 명시: 앱 미접속, 접속 후 루틴 미생성, 루틴 생성 후 운동 미시작, 운동 시작 후 0블록 중단 모두 휴식이다. 휴식 버튼은 의도적으로 제거했으므로 사용자 선택·API 호출·세션 존재를 휴식 기록의 전제조건으로 삼지 않는다. 세션 없는 날의 서버 일별 결과 조회·집계는 아직 구현하지 않았다.

## 인수 조건

1. 사용자 화면의 미수행 표시를 휴식에 통합한다. 캘린더의 월/주 집계와 범례는 완료·부분 수행·휴식 세 항목이다.
2. 캘린더와 주간 리포트의 휴식은 기존 루틴 휴식 버튼의 달 아이콘을 공유한다.
3. 체크인 이후 휴식 선택 버튼과 연결 콜백은 실제 화면과 미리보기에서 노출하지 않는다. 기존 `HomeRoutineCard.tsx`의 버튼 디자인과 `homeStyles.tsx`의 스타일은 보존한다.
4. 완료 블록 0개로 중단을 확정하면 기록 저장 성공 후 피드백 없이 홈으로 돌아간다.
5. 완료 블록이 있는 중단은 서버의 부분 수행/완료 결과를 표시한다. 피드백 선택 전 저장 버튼은 비활성화하며, 성공 후 홈으로 이동한다. 별도의 홈으로 버튼은 없다. 저장 실패 시 선택과 재시도 버튼을 유지한다.
6. 안전 중단은 기존 안전 API를 사용한다. 완료 블록이 없는 경우 홈으로 이동하되 서버 안전 안내를 유지한다.

## 계약과 제한

- API, DB, 백엔드 코드와 저장 상태를 변경하지 않는다. `NOT_COMPLETED`는 세션의 기존 전송 코드이며 UI 명칭은 휴식이다. 결정의 `REST`와 구분한다.
- 현재 `/finish`는 블록 0개 종료를 거부한다. 따라서 기존 중단 사유를 선택한 후 `/not-completed`로 저장하고 홈으로 이동한다. 사유 선택까지 생략하는 즉시 저장은 현재 백엔드 계약으로 지원할 수 없다. 임의의 사유를 자동 전송하지 않는다.
- 주간 리포트의 `counts.not_completed` 등 공개 필드와 서버 집계값은 유지한다.
- 안전 판단, 블록 기반 수행 판정, 개인정보 수집과 로깅은 변경하지 않는다.

## 구현·검증 계획

1. 공용 상태 문구, 캘린더 표시 모델과 달 아이콘을 통합한다.
2. 홈 휴식 진입점을 제거하고 운동 중단의 결과 이동을 연결한다.
3. 피드백 저장 성공/실패와 홈 복귀, 휴식 집계, 버튼 미노출을 테스트한다.
4. 프론트 포맷·린트·타입 검사, 전체 테스트, Android/iOS production export를 실행한다.

## 수동 확인

- 체크인 완료 후 휴식 버튼이 렌더링되지 않는지 확인한다.
- 블록 0개 중단 사유를 선택해 중단을 확정하고, 피드백 없이 홈과 캘린더의 휴식 기록을 확인한다.
- 블록 1개 격파 후 중단하고, 피드백 선택 전/후 버튼 상태와 저장 후 홈 복귀를 확인한다.
- 캘린더의 휴식 범례·날짜 표시와 주간 리포트의 달 아이콘을 확인한다.
