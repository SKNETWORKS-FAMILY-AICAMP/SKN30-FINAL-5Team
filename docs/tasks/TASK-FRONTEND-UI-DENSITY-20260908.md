# 홈·체크인·운동 진행·알림 UI 후속 개선

- Owner: frontend
- Branch: `feat/frontend-UI-0908`
- 인수 기준: 2026-09-08 사용자 요청 1~10 및 통증 안내 문구 후속 정정

## 적용 내용

- 홈의 인사말·날짜·주간 카드 간격과 카드 상하 여백, 요일 간격을 줄이고 체크인 CTA를 58→52 기준 단위로 축소한다. 홈 구조, 카드 radius, 알림 버튼과 마스코트 크기는 유지한다.
- 체크인 헤더와 질문 문구를 간결하게 바꾸고, 서버의 권장 시간을 `1회 권장 운동 시간: N분`으로 시간 선택 칸 바로 아래에 표시한다. 후속 요청에 따라 별도 배경 박스 없이 운동 가능 시간의 흰색 카드에 직접 배치한다. 권장값이 없으면 선택 가능한 10~90분 범위를 안내한다. 권장값은 선택 상한이 아니다.
- 체크인 카드 padding·radius·간격, 헤더와 하단 여백을 줄인다. 선택 버튼과 시간 증감 버튼은 최소 44px 터치 영역을 유지한다.
- 통증 기본 부위는 어깨/허리, 무릎/목, 손목·손/발목·발 순서로 6개를 표시한다. 팔꿈치·등 위쪽·고관절·가슴·복부는 펼치기에 둔다. 선택 가능한 기존 코드 집합과 저장된 통증 강도는 유지한다. 추가 부위가 저장되어 있으면 처음부터 펼친다.
- 통증 선택 안내는 `통증이 있는 부위를 모두 선택해주세요.`로 통일한다. 최초에는 일반 안내이며, 통증 있음·부위 미선택 상태로 제출하면 같은 문구를 중복 없이 접근성 alert로 전환한다. 부위를 선택하면 오류 상태를 해제한다.
- 위험 신호 카드는 기존 경고 색상을 유지하고 `운동 전 확인이 필요해요` 아래 증상 4개와 없음/있음 선택을 표시한다. 미선택 오류는 제출 시에만 표시하고, 안전 입력 누락 시 저장하지 않는다. 전송 중과 장소 선택지 로딩 실패 상태는 제출 버튼을 비활성화한다.
- 운동 원형 영역에는 로컬 `monkey_run.gif`가 연결되어 있다. 파일은 480×480, 4프레임이며 빈 파일이 아니다. 기존에는 로딩·실패 대체 표시가 없었다. 기존 운동 완료 끼끼 PNG를 기본 표시하고 GIF 로딩 성공 시 애니메이션을 덮어 표시하며, 실패 시 PNG를 유지한다.
- 알림 카드의 상하 padding, 제목·본문·날짜 간격과 카드 사이 간격을 줄인다.

## 계약·보안·제한

- 공개 API, DB 스키마, 안전 판단 규칙, 수집·저장·로그 항목 변경 없음. 추가 production 의존성 없음.
- 실제 기기에서 발생한 GIF 빈 영역의 원인은 재현하지 못했다. 이번 수정은 로딩 중·표시 실패 시 빈 영역 방지다. GIF는 특정 운동 자세 영상이 아닌 기존 공통 마스코트다.
- 실제 기기의 화면 밀도와 GIF 재생은 아래 수동 확인 절차로 확인해야 한다.

## 수동 확인 절차

1. 390×844 및 작은 모바일 화면에서 홈의 기존 구조·radius·끼끼 크기를 확인한다.
2. 체크인을 열어 헤더·질문 문구, 권장 시간 위치, 추가 질문 노출 정도, 버튼 터치 영역을 확인한다.
3. 통증 있음 선택 후 기본 6개 및 펼치기의 나머지 부위를 확인한다. 저장된 추가 부위와 통증 강도가 유지되는지 확인한다.
4. 통증 부위와 위험 신호를 미선택한 채 제출해 오류 안내를 확인하고, 입력 후 오류 해제와 정상 제출을 확인한다.
5. 운동 진행에서 GIF 로딩 전·로딩 성공·실패 상태의 끼끼 표시와 안전 중단 시 진지한 안내 화면을 확인한다.
6. 알림 3개 이상에서 카드 밀도, 스크롤, 읽음 처리 동작을 확인한다.
