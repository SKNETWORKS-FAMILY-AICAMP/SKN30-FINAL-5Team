# Task Documents

한 이슈의 범위, 인수 조건, 위험, 인계물을 저장한다. 작업 시작 전 `TEMPLATE.md`를 복사하고 이슈 번호를 파일명에 포함한다.

완료된 문서는 삭제하지 않고 구현 PR과 연결한다. 제품 요구 변경은 task 문서만 수정하지 말고 해당 source-of-truth 문서와 ADR을 함께 갱신한다.

## 착수 게이트

새 작업은 `IN_PROGRESS`로 전환하기 전에 다음 항목이 채워진 task 문서를 먼저 만든다.

- 실제 검증 가능한 인수 조건
- 요구사항 ID와 영향받는 API·DB 계약
- 변경 예상 파일과 primary owner
- 테스트 계획과 수동 확인 절차
- 보안·개인정보·호환성 영향
- 선행 관계와 명시적 제외 범위

`TBD`, 제목 반복, 구현 방법만 적은 항목은 인수 조건으로 인정하지 않는다. GitHub issue가 아직
발급되지 않았다면 임시 task ID를 사용할 수 있지만, issue 발급 즉시 파일명·본문·브랜치 연결을
갱신한다. 구현 PR이 병합되면 상태, PR 번호, merge commit, 실제 실행한 테스트 결과를 task 문서에
남긴다.
