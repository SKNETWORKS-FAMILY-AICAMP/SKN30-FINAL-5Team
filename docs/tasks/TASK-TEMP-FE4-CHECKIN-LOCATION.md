# FE-4 체크인 장소 선택 UI

## 범위

- 기반 브랜치: `refactor/temp-fe14-home-screen-split`
- 작업 브랜치: `feat/temp-fe4-location-after-fe14`
- 프론트엔드만 변경한다.
- BM-4가 추가한 `DailyContextDefaultsResponse.selectable_location_codes`를 장소 선택의 유일한 출처로 사용한다.

## 구현 계획

1. 체크인 기본값 응답 타입에 서버 장소 선택지를 추가한다.
2. 프로필의 legacy 장소 필드를 체크인 경로에서 제거한다.
3. 서버 선택지 중 `HOME`, `GYM`만 노출하고 기존 `OUTDOOR` 컨텍스트는 읽되 선택지로 노출하지 않는다.
4. 오늘 저장값, 전날 저장값, 서버 선택지 첫 항목 순으로 기본 선택값을 정한다.
5. 서버 장소 선택지가 없거나 유효한 장소가 선택되지 않으면 체크인 저장을 막고 오류 상태를 표시한다.
6. 서버 선택지·전날 기본값·OUTDOOR 비노출·저장 payload를 컴포넌트 테스트로 검증한다.

## 위험 및 호환성

- API/DB 스키마를 변경하지 않고, 이미 병합된 additive BM-4 응답을 소비한다.
- 구버전 서버가 장소 선택지를 누락하면 프로필 값이나 하드코딩 값으로 저장하지 않고 재시도 안내를 보여준다.
- `OUTDOOR` 타입과 기존 저장값은 유지한다. 사용자에게 제공하는 선택지에서만 제외한다.
- 인증 정보나 건강 데이터를 새로 저장하거나 로그에 남기지 않는다.
