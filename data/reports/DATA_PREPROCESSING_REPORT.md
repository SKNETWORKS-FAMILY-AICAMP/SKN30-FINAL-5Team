# 데이터 전처리 보고서

## 1. 결론

원천과 정규화 데이터를 분리하고, 중복·불명확·고난도 후보를 제외한 뒤 50개 운동을
정규화한 **MVP DRAFT 전처리 단계가 완료**됐다. 두 트랙의 리뷰 결과 검증, 카탈로그
시드 검증, 안전 규칙 검증을 통과했으며 미결 리뷰는 없다.

다만 `DOMAIN_APPROVED`와 `TECH_REVIEWED`는 기존 파이프라인이 요구하는 호환 상태 코드다.
실제 방법은 `AGENT_ONLY`, 상태 해석은 `PIPELINE_COMPATIBILITY_ONLY`, 운영 가능 여부는
`production_eligible=false`이다.

## 2. 처리 흐름

1. 원천 JSON을 변경 불가능한 스냅샷으로 보존하고 파일별 SHA-256을 기록했다.
2. KSPO 프레임 행을 파일-운동명 후보로 집계하고, wger 운동·번역·장비·라이선스를 결합했다.
3. MVP 범위와 증거 수준에 따라 KSPO 50개, wger 60개 리뷰 배치를 만들었다.
4. 기존 포함 24개를 보존하고 미결 86개를 26개 포함, 60개 제외로 완전 분할했다.
5. 포함 50개에 stable code, 한국어 표시명, taxonomy, 난이도, 시간, 부위, 장비, 위치,
   실행 안내와 자세 큐를 부여했다.
6. 정규화 속성으로 트랙별 카탈로그 시드를 생성하고, 두 시드를 결합해 안전 규칙을 생성했다.
7. 새 시드는 입력 리뷰 배치·매핑·증적·속성·taxonomy의 해시를 기록하며 안전 규칙은
   입력 시드 매니페스트와 운동 파일 해시를 기록한다.

## 3. 리뷰 결정

| 구분 | KSPO | wger | 합계 |
|---|---:|---:|---:|
| 기존 포함 | 10 | 14 | 24 |
| 이번 포함 | 13 | 13 | 26 |
| 최종 포함 | 23 | 27 | 50 |
| 제외 | 27 | 33 | 60 |
| 미결 | 0 | 0 | 0 |

제외 원칙은 다음과 같다.

- 기존 포함 운동과 기능적으로 중복되는 변형
- 원천 운동명만으로 동작을 안전하게 특정하기 어려운 후보
- 초보 MVP에 부적합한 고충격·고기술 동작
- 현 taxonomy·장비 코드로 정확히 표현할 수 없는 후보

불확실한 후보를 억지로 정규화하지 않고 제외하는 fail-closed 원칙을 적용했다.

## 5. 정규화 및 품질 규칙

- stable code와 한국어 표시명은 50개 모두 고유하다.
- 한국어 표시명을 DB 키로 사용하지 않고 영문 stable code를 사용한다.
- 원천 ID, 원천 트랙, 라이선스·미디어 권리 상태를 삭제하지 않았다.
- 원천의 세트·반복·시간 누락이 높아 기본 실행량은 taxonomy와 보수적 DRAFT 정책으로
  작성했으며 원천 처방으로 오인하지 않는다.
- 동작 안내는 원문을 복제하지 않고 일반적인 수행 정보로 새로 작성했다.
- 전환 시간은 도메인 규칙 범위인 10~20초 안의 15초로 통일했다.
- REPS는 초당 반복 시간, DURATION은 작업 시간을 사용하도록 상호 배타적으로 정규화했다.
- 원천 근육명은 운동 안전 금기 근거로 직접 사용하지 않고 검토된 body area만 안전 규칙에 썼다.

| 산출물 | 레코드 | 결과 |

| KSPO 카탈로그 시드 `kspo-mvp-v0.2.0` | 23 | valid |

안전 규칙 커버리지 보고서는 50개 운동에 대해 목, 어깨, 팔꿈치, 손목·손, 등,
허리, 엉덩이, 무릎, 발목·발, 가슴, 복부, 전신, 기타의 MILD/MODERATE 상태별
제외·주의·선택 가능 개수를 제공한다. 이 규칙은 진단이나 치료가 아니라 명시적인
불편 부위 입력에 대한 보수적 루틴 필터다.

## 7. 적합성 판단

현재 전처리는 MVP DRAFT 용도로 적합하다.

- 원천과 정규화 데이터가 분리돼 있다.
- 모든 리뷰 후보에 결정이 있고, 포함 행은 네 역할 증적을 갖는다.
- 정규화 코드와 속성이 검증기 및 taxonomy를 통과한다.
- 입력·출력 해시로 시드와 안전 규칙을 재현할 수 있다.
- 외부 전문가 미검증과 production 금지를 매니페스트에 기계 판독 가능하게 남겼다.

운영용으로는 아직 적합하지 않다. 특히 외부 전문가 승인 없이 개별 금기나 재활·치료
목적으로 사용하면 안 된다.

## 8. 남은 작업과 추가 수집 판단

추가 수집보다 먼저 수행할 작업은 다음 순서다.

1. 50개 안에서 목표·부위·장비·위치별 대체 관계를 DRAFT로 생성한다.
2. 필수 golden scenario와 안전 veto, LLM 실패 fallback으로 실제 선택 가능 개수를 검증한다.
3. 중복 문구, 과도한 의료 표현, 라이선스 귀속 표시를 자동 검사한다.
4. 위 검증에서 빈 패턴이나 대체 운동 부족이 확인된 영역만 선택적으로 추가 수집한다.

현재 확인된 잠재적 보강 영역은 유산소, 모빌리티, 균형·민첩성이다. 그러나 “개수가 적다”는
이유만으로 즉시 수집하지 않고, 루틴 생성 테스트에서 요구량 미달이 증명될 때 수집한다.

## 9. 알려진 제한

- 에이전트 검토는 외부 전문가 검증을 대체하지 않으며 위험을 0으로 만들지 못한다.
- `beginner_suitable=false` 22개는 서비스에서 조건부 또는 대체 후보로만 써야 한다.
- 대체 관계는 아직 생성 전이므로 현재 산출물만으로 자동 대체 품질을 보장할 수 없다.
- 사용자 반응·완료·스킵 실데이터가 없어 개인화 효과나 편향을 평가하지 못했다.
- 운영 DB 적재, API 연결, 프론트 노출은 이번 범위에 포함되지 않았다.
