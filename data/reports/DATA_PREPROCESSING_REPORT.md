- 데이터 상태: `DRAFT`, `AGENT_ONLY`, `production_eligible=false`

## 1. 전처리 개요

전처리 목적은 KSPO·wger의 서로 다른 원천 구조를 통합 가능한 운동 마스터로 정규화하고,
FITT·강도 참고, 안전 규칙, 대체 관계를 원천과 분리해 멀티 에이전트가 재현 가능한
구조화 데이터로 조회하도록 만드는 것이다.

범위는 원천 무결성 검증, 후보 집계·프로파일, 검토 결정, 중복·불명확 후보 제거,
taxonomy·속성 정규화, 안전 규칙·대체 관계 생성, 골든 시나리오 검증까지다. ML/DL
학습용 데이터가 아니므로 Train/Validation/Test 무작위 분할은 적용하지 않았다.

사용 도구는 Python 3.12, 표준 JSON/CSV·해시 처리 모듈, 프로젝트 검증 스크립트,
pytest, ruff, mypy다.

## 2. 원천 진단과 전처리 원칙

| 이슈 | 대상 | 판정·규모 | 처리 |
|---|---|---|---|
| 반복 프레임 | KSPO | 1,668행이 243개 영상에 반복 연결 | 파일명+운동명 단위 후보로 집계 |
| 운동명 누락 | KSPO | 15행 | 후보 생성에서 제외 |
| 다중 운동명 | KSPO | 49개 영상 | 파일 단위 자동 병합 금지 |
| 실행량 결측 | KSPO | 세트·반복·시간·주기 약 84~86% 누락 | 원천 처방으로 사용하지 않고 별도 DRAFT 기본값 작성 |
| 한국어 번역 부재 | wger | 862개 중 한국어 번역 0개 | 한국어 표시명·안내를 별도 검토 필드로 작성 |
| 장비 근거 누락 | wger | 헬스장 후보 400개 중 근거 377개 | 이름으로 자동 보완하지 않고 증거 부족 후보 제외 |
| 중복·세부 변형 | 양 원천 | 기능 중복 후보 | stable code·표시명·원천 ID 중복 검사 후 대표 후보만 포함 |
| 고난도·불명확 동작 | 양 원천 | 초보 MVP 또는 현 taxonomy에 부적합 | EXCLUDE와 근거 코드 기록 |

불확실한 데이터를 추정해 채우지 않고 제외하는 fail-closed 원칙을 사용했다. 원천 근육명,
설명, MET 활동명을 통증 금기나 운동별 강도로 자동 변환하지 않았다.

## 3. 처리 파이프라인

1. API·공식 문서 응답을 불변 스냅샷으로 저장하고 파일별 SHA-256을 기록했다.
2. KSPO는 프레임을 파일-운동명 후보로 집계하고 wger는 운동·번역·장비·라이선스를 결합했다.
3. 프로파일에서 MVP 검토 배치를 만들고 총 121건을 INCLUDE 56·EXCLUDE 65로 분할했다.
4. 포함 행에 stable code, 한국어명, taxonomy, 난이도, 시간, 부위, 장비, 위치, 안내를 부여했다.
5. 기존 50건과 tranche 3 증분 6건을 분리된 카탈로그 시드로 생성했다.
6. 56건 전체에서 안전 규칙 354건과 목표 보존 대체 관계 238건을 생성했다.
7. 기존 6건과 신규 5건의 골든 시나리오를 실행하고 매니페스트 해시를 검증했다.

## 4. 정규화 규칙

- 한국어 표시명은 키로 사용하지 않고 고유 영문 `stable_code`를 사용한다.
- 원천 identity·트랙·라이선스·미디어 권리 상태를 삭제하지 않는다.
- taxonomy 허용 코드만 사용하며 새 코드를 임의 생성하지 않는다.
- `REPS`는 `default_seconds_per_rep`, `DURATION`은 `default_work_seconds`를 사용한다.
- 전환 시간은 도메인 범위 10~20초 안에서 15초로 통일했다.
- 원천 처방량·근육명·의료 표현을 안전·금기 규칙으로 자동 승격하지 않는다.
- 안전 규칙은 검토된 body area와 결정적 심각도 정책에서만 생성한다.
- 대체 관계는 목표 보존 그룹 안에서 난이도를 높이지 않으며 최종 안전 필터를 별도 적용한다.

골든 결과를 임시 위치에 재생성해 8개 파일이 기존 산출물과 바이트 단위로 동일함을 확인했다.

## 7. 후속 활용과 재현성

- 운동 카탈로그: 루틴 후보 조회용 DRAFT seed
- FITT·강도 참고: 주간 계획과 강도 분류의 공중보건 참고값
- 안전 규칙: 명시적 불편 부위·심각도에 따른 결정적 제외·주의 필터
- 대체 관계: 위치·장비·난이도·불편 상황에서 목표를 보존하는 후보 관계
- 골든 시나리오: 건강 상태 원안 유지, 불편 부위 제외, 안전 veto, 폴백 검증

각 생성물 매니페스트에는 입력 경로, SHA-256, 바이트 수, 레코드 수, 정책 버전과
`production_eligible=false`가 기록된다. 부분 실패 시 최종 디렉터리를 만들지 않으며 기존
버전을 덮어쓰지 않는다.

## 8. 적합성·제한 및 변경 이력

현재 결과는 MVP 데이터 파이프라인·규칙 검증용으로 적합하지만 운영 추천용은 아니다.
`DOMAIN_APPROVED`는 생성기 호환 상태이며 외부 운동·의료 전문가 승인을 뜻하지 않는다.
한국어 안내와 초보자 적합성은 에이전트 검토 결과이므로 진단·치료·재활·처방 목적으로
사용할 수 없다.

카탈로그가 근력 중심이고 실제 사용자 수행·스킵 데이터가 없어 개인화 효과와 편향을
평가하지 못했다. 운영 DB 적재, API 연결, 프론트 노출은 이번 범위에 포함되지 않는다.
